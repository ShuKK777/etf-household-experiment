# 原始脚本 → 仓库模块

实验最初是二十几个平行脚本，每个直接写死路径、各自复制一段 bootstrap。
本仓库把它们按职责收进 `etf_experiment/`。这张表说明**每一份原始脚本去了哪里**，
以便任何人拿着旧目录都能找到对应实现，而不是怀疑代码被丢了。

## 唯一没有搬迁的：第六轮的题面构建器

`run3_20261030/build_tasks.py`（381 行）把 34 个实验的题面转成引擎任务行。
它没有搬进包，原因有两条：

1. **它依赖实验包自带的渲染器。** 题面由 `共享/render.py` 统一渲染，而那个渲染器随
   34 实验包发布（`3etf_实验包_20261030.zip`），不在本仓库。搬迁过来会多一份需要同步的副本。
2. **它是一次性的转换器。** 34 个实验的题面已经在包里定稿，转换只做一遍。与
   `conditions.py` 那种"措辞本身就是处理变量、必须逐字冻结"的模块不同，它不需要
   成为长期维护的接口。

**它的作用、输入与口径已经完整记录**在：

- `docs/设计文档/实验包_34个实验索引.md` — 每个实验改了什么
- `docs/设计文档/实验包_README.md` — 目录、编号规则、共用设置
- `docs/设计文档/实验包_交付说明.md` — 三条必须守住的口径

也就是说：这一轮的**设计和题面**在仓库里，**转换脚本**留在实验包内。要重跑第六轮，
需要先解压实验包，再在包内执行其自带的构建流程。

## 一并消失的临时产物

这些没有入仓库，因为它们能从代码重算：

| 产物 | 体积 | 重算方式 |
|---|---|---|
| `results/lane*/`、`results/by_order/` | ~530 MB | `cli tasks` → `cli run` → `cli rescore` |
| `factorial/results/cell_*.npz` | 37 MB | `cli factorial` |
| `probes/results/*.npz` | 8 MB | `cli probes` |
| `tasks*`、`lanes*`、`logs/` | ~2 GB | `cli tasks`、`cli run` |
| `models/` | 11 GB | 见 README 的 Hugging Face 说明 |

## 验证代码没走样

搬运不等于改写。`docs/重算一致性.md` 记录了逐字节比对的结果：六张表完全一致，
一张表 90 行里 2 行差 1e-6（浮点累加顺序）。题面则通过 15 个条件的逐字比对锁定。
