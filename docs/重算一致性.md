# 重算一致性

这份记录回答一个问题：**用本仓库的代码重跑，能不能得到与已发表表相同的数字？**
答案按表分档，并写明每一处不一致的原因，而不是笼统地说"可复现"。

## 方法

用仓库里的模块从归档的逐户结果重算每张表，然后与已发表的 CSV 做**字节级比较**（`cmp`）。
不是比较统计量是否"接近"，而是比较每一个字节。

```bash
python -m etf_experiment.cli tables --results <逐户结果> --out out/tables
python -m etf_experiment.cli factorial-tables --cells results/factorial --out out/factorial
python -m etf_experiment.cli probe-tables --probes results/probes --out out/probes
python -m etf_experiment.cli teacher-table --teacher results/probes/teacher27b \
    --cells results/factorial --out out/probes
```

## 唯一的两处差异

| 因子 / 档位 / 组别 | 列 | 本仓库 | 已发表 |
|---|---|---|---|
| 门槛 / 门槛100元 / 资产b1 | `纯债_下限` | −0.006779 | −0.006780 |
| 门槛 / 门槛10000元 / 资产b3 | `离开存款_上限` | 0.001345 | 0.001346 |

两处都是**区间端点**的第 6 位小数，点估计全部相同。

原因是 bootstrap 内部 `np.sum` 的**浮点累加顺序**：同一组抽样下，先乘后加与先加后乘
在最后一位上有差别。抽样本身完全相同（种子、次数、抽样矩阵都一样）。

这不是需要修补的 bug，而是浮点运算的固有性质。判断依据：**同一份代码重跑两次，结果会在
这个量级上稳定复现**（NumPy 的求和顺序在同版本下确定），换一个 NumPy 版本才会变。

## 为什么能做到字节级

三个容易踩的坑，都已处理并在测试里盯住：

**1. 行尾符。** `csv.writer` 默认写 `\r\n`。两族表的历史格式不同——因子设计的三张表是
CRLF，探针的四张是 LF。`write_csv` 因此把行尾作为参数，各模块按自己的历史格式写。
否则一次重跑会把每一行都标成 changed，真正的内容改动反而看不出来。

**2. 指标的排列顺序。** 词汇表里三个权益 ETF 分开在前、合计在后，而不是反过来。
顺序不同时数值完全一样，但 `diff` 会显示全表变化。

**3. 随机流的复用方式。** 每格新建一个 generator，而不是共用一个流。
共用会让第一个指标之后的每个区间都偏移，因为抽样矩阵从流里的位置不同。

## 条件模板的逐字校验

比表格更关键的是**题面**。条件文本、指令和六个选项必须与当初实际打分的输入逐字相同，
否则重跑得到的是另一套处理变量。

`tests/fixtures/` 存了十五个条件各一条完整的 `state` 与 `questions`（31 KB），
`tests/test_experiment.py::test_condition_text_matches_frozen_inputs` 逐字比对。

重建期间这个测试抓到了 31 处差异，全部来自金额格式化：`X` 被渲染成 `62,500.00`
而不是 `62,500`。已修正。

## 第二拍与安慰剂的句子

两拍闭环的追加句子按第一拍的最高选项生成，五种情形各不相同；句子安慰剂的真句与对照句
必须等长且对照句不含任何处理词汇。

验证方式：用 1,200 条**实际跑过的**第二拍任务比对，句子与题目金额全部逐字复现；
对照句与真句同为 58 个字符。
