# 交付说明（ laya）

这份包是用来做**完整实验**的：34 个实验，全部在**同一批 10,000 户**上跑，画像统一用
**五维补全**的方式生成。每个实验一个文件夹，文件夹名以编号开头，编号顺序就是报告里
《二、全部实验的总表》的顺序（0 号＝整笔单选普通条件，1 号＝整笔单选＋产品解释，以此类推）。

## 一、先看这三份

| 文件 | 看什么 |
|---|---|
| `README.md` | 全局：目录、编号表、口径注意事项 |
| `共享/五维补全/README.md` | 五维补全怎么做的、五个字段是什么、当前跑到哪了 |
| 任意 `NN_*/说明.md` | 单个实验：来源、用哪套画像、题面要素、户数与调用量、分析口径 |

## 二、跑一个实验需要什么

每个实验文件夹里：

```
说明.md          这个实验是什么、用哪套画像
题面.md          完整题面（system + user 模板 + 字段说明）
prompt.json      机读题面
选择输入.json     可选产品 / 菜单规则 / 输出契约
build_inputs.py  渲染脚本
样例.jsonl       已渲染好的样例（先看这个确认题面对不对）
```

渲染全量：

```bash
cd 08_补全五维画像_自由填写
/usr/bin/python3 build_inputs.py
```

输出的 `inputs.jsonl` 每行是一条可直接发送的请求：`payload.messages` 就是 system + user 两段，
`payload.model` 为 `deepseek-flash`，`temperature` 为 0。`payload_sha256` 可用于核对是否被改动。

## 三、口径上必须守住的三条

**1. 户数是 10,000，不是报告里的 91 / 257 / 776。**
报告里那些数字是在子群上算的。本包全部在 10,000 户上跑，子群结论要在这批结果里重新切分后计算。
画像池里保留了 `asset_bracket`、`risk_preference`、`stratum_id`、`normalized_weight`，
但历史子群的成员名单**不能沿用旧名单**，需要在新基线结果上重新冻结。

**2. 输出格式是大效应，15 和 16 必须分开跑、分开报。**
15 号输出菜单编号（`Pxx`），16 号输出六键金额，两者是同一条件、同一菜单、同一门槛。
报告 5.4 节指出这里可能有 3 倍差距，所以它们是两个独立实验，不能合并。

**3. 五维补全是合成设定，不是真实观测。**
补全块在题面里以「补充投资画像：」单独成块显示，与原 36 字段画像明确分开。
任何"补全导致份额变化"的结论都只能当**合成画像的效应**，报告 5.1 节已注明这类结果不可对外。

## 五、依赖

`jsonschema`、`aiohttp`。只有系统 `/usr/bin/python3` 装了这两个，anaconda 那个环境没有。
所有脚本都用 `/usr/bin/python3` 跑。

## 六、如果要改题面

不要直接改各文件夹里的 `prompt.json`——它和 `共享/render.py` 的渲染逻辑是配套的。
改 `共享/render.py` 或 `_构建/build_folders.py` 后重跑：

```bash
cd _构建
/usr/bin/python3 build_folders.py
```
